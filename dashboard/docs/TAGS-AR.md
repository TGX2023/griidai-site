# Tags في البلوجز والـUse Cases

افتح السجل في Content Manager، ثم خانة **Tags**:

1. اكتب موضوعًا واضحًا مثل Solar Energy أو Remote Sensing.
2. اضغط Enter أو Add tag. الفاصلة تفصل بين أكثر من Tag، ويمكن لصق قائمة مفصولة بفواصل أو أسطر.
3. اقتراحات الخانة تأتي من محتوى يملك حسابك صلاحية قراءته. يمكنك كتابة موضوع جديد مباشرة.
4. زر × يحذف الـTag من السجل الحالي. اختلاف الحروف الكبيرة والصغيرة لا ينشئ نسخة مكررة.
5. الحد الأقصى 12 Tag، وكل واحدة حتى 50 حرفًا. الكلمات العربية مدعومة، ولا يُسمح بـHTML.
6. Save يحفظ مسودة. Publish يحدّث الكارت والصفحة والفلترة عند الفتح أو Refresh؛ حفظ المسودة لا يغير الـTags المنشورة.

تظهر الـTags على الكارت وأعلى الصفحة الداخلية وفي المعاينة. الضغط عليها يفتح قائمة البلوجز أو الـUse Cases مفلترة بنفس الموضوع. **Filter by tag** يختار موضوعًا آخر، وClear filter يعرض الكل. البحث النصي داخل القائمة يشمل الـTags أيضًا. إذا كان فلتر Tag مفعّلًا، يبحث داخل نتائجه.

الفلترة تُنفَّذ على السيرفر وتعمل بدون JavaScript، وتعرض المنشور فقط. تغيير الـTags أو إلغاء نشر المحتوى ينعكس على النتائج دون إعادة بناء الموقع. لا نُنشئ صفحات أرشيف منفصلة لكل Tag؛ عنوان canonical للقائمة المفلترة يظل عنوان القائمة الأساسي.

الـTags تصف موضوعات ظاهرة للزوار. **Target search phrase** تظل ملاحظة داخلية للتخطيط. لا تُضاف الـTags كتاج meta keywords، ولا تعطي ضمانًا لترتيب أعلى في Google.

## للتيم

- أُضيف حقل JSON `tags` بمحرر `global::content-tags` إلى نوعي المحتوى، دون علاقة بجدول زوار أو إعدادات التسعير.
- `shared/tags.cjs` ينظف القيم ويمنع التكرار، ويجهز روابط وفلاتر العرض.
- صلاحيات read/create/update للحقل مضافة إلى أدوار الماركتنج القائمة؛ صلاحية النشر لم تتغير.
- لا توجد متغيرات بيئة جديدة. الكود وحده لا ينقل قيم الـTags التي أدخلها التيم؛ انقل قاعدة البيانات مع المحتوى عند النشر.
- التحقق: `npm test` ثم `node scripts/prepare-qa.cjs` و`node scripts/tags-qa.cjs` و`node scripts/cleanup-qa.cjs`.
