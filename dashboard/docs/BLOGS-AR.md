# إدارة بلوجز GriidAi

## أين تظهر؟

- القائمة: `http://localhost:3000/blogs/`، مع بحث بالعنوان والوصف والتصنيف واسم الكاتب.
- لكل مقال رابط مستقل: `/blogs/<slug>/`.
- رابط Blogs في شريط التنقل والفوتر، وخريطة الموقع تشمل المقالات المنشورة القابلة للفهرسة فقط.
- نستخدم نفس سيرفر الموقع وStrapi وقاعدة البيانات ومكتبة الصور؛ لا توجد منصة بلوجز ثانية أو روابط Industries / Workflows.

## الماركتنج

من Content Manager → Blog افتح مقالًا أو اضغط Create new entry.

1. اكتب عنوان المقال، وصفًا مختصرًا للكارت، التصنيف والرابط. الرابط يُقترح من العنوان ويُقفل بعد أول نشر.
2. اختر صورة الغلاف وأضف وصفها. Zoom وHorizontal / Vertical focus يحددان القص نفسه للكارت والصفحة الداخلية.
3. أدخل اسم الكاتب ورابط LinkedIn الشخصي الحقيقي إن توفر، ثم اختر **Author photo** من مكتبة الصور. يفضّل رفع صورة مربعة واضحة بمقاس 400×400 أو أكبر؛ تظهر في دائرة صغيرة بدل الحرف على الكارت وفي أعلى وأسفل المقال، وكذلك في المعاينة أثناء التعديل. لو لم تختَر صورة، يظل الحرف ظاهرًا. أدخل تاريخ النشر الأصلي؛ التاريخ مستقل عن تاريخ رفع المقال إلى Strapi.
4. اكتب المقال في Article content: عناوين وفقرات وقوائم وروابط وتنسيق النص، بنفس محرر المحتوى الحالي.
5. يمكن إضافة رابط المقال الأصلي وتعديل SEO & Sharing، وعنوان ووصف البحث قابلان للتخصيص كما في Use Cases. عنوان ووصف المشاركة يتبعان الصفحة دائمًا، ويمكن تخصيص صورة المشاركة فقط. canonical والفهرسة واتباع الروابط تلقائية وغير قابلة للتغيير من اللوحة.
6. المعاينة الجانبية تعرض التعديلات أثناء الكتابة، مع وضع الموبايل ومعاينة الكارت. رابط Open preview يعرض المسودة المحفوظة فقط.
7. Save يحفظ مسودة. Publish يعرضها للزوار عند الفتح أو Refresh. Unpublish يخفي الكارت والرابط الداخلي؛ لا توجد نسخة HTML قديمة احتياطية تظهر بدلًا منها.

الاسم والتاريخ ورابط LinkedIn عند إضافته تظهر تحت محتوى الكارت وداخل صفحة المقال. لا نضع رابط LinkedIn تخمينيًا أو رابط بحث بدل حساب الكاتب.

## المقالات التجريبية المنقولة

الأداة `node scripts/import-techgx-blogs.cjs` تنقل ثلاثة مقالات GriidAi من TechG-X: معرّفات WordPress هي 175 و141 و137. تقرأ النص الكامل وتحوّله إلى مستند منظم، مع العناوين والفقرات والقوائم والتنسيق والروابط المسموحة، وتنقل الصور إلى Media Library وتحتفظ بالتاريخ الأصلي واسم الكاتب المنشور ورابط المصدر. لا تنقل HTML أو سكربتات أو CSS المصدر إلى صفحة الموقع.

الكاتب في بيانات المصدر لهذه المقالات هو **adminTGX**، ولا تتضمن بياناته رابط LinkedIn. لذلك حُفظ الاسم كما هو، وتُرك رابط LinkedIn فارغًا لتصحيحه من التيم. الملخصات القصيرة للكروت صيغت للموقع الجديد.

الاستيراد يحافظ على السجلات التي لها نفس importKey؛ إعادة تشغيله لا تكررها ولا تستبدل تعديلات الماركتنج. لا تستعمله لإعادة نشر مقال أُلغي نشره. رفع الكود وحده لا ينقل قاعدة البيانات أو ملفات الصور.

## التيم والتشغيل

- نوع المحتوى: `api::blog.blog`، وواجهات القراءة: `/api/blogs` و`/api/blogs/:documentId`.
- الموقع يستخدم نفس `STRAPI_URL` و`STRAPI_PUBLIC_URL` و`STRAPI_API_TOKEN` و`SITE_URL` و`PREVIEW_SECRET` الموجودة في ملفات البيئة المتجاهلة. لا تُرسل التوكنات إلى المتصفح.
- توكن القراءة يحتاج `api::blog.blog.find` و`api::blog.blog.findOne` بالإضافة إلى صلاحيات Use Cases. توكن التجربة المحلي المسمّى GriidAi local website يُوسّع تلقائيًا بهاتين الصلاحيتين فقط، دون تغيير قيمته. في النشر اضبط صلاحيات توكن الموقع من لوحة Super Admin.
- Marketing Editor يقرأ ويضيف ويعدل ويحفظ ويعاين. Marketing Publisher ينشر ويلغي النشر أيضًا. إدارة الحسابات والإعدادات تبقى Super Admin فقط، والتسجيل العام مقفول.
- المعاينة موقعة ومحدودة المدة، بتوقيع منفصل عن Use Cases. لا يكفي `preview=true` لقراءة المسودات. المعاينة دائمًا noindex/no-store، والمحتوى العام يقرأ published فقط مع Pagination.
- BlogPosting وOpen Graph وcanonical واسم الكاتب وتواريخ النشر تُولّد من نفس السجل. لا تتغير إعدادات التسعير ضمن هذا العمل.

## التحقق

شغّل `npm test` للاختبارات الأساسية. ثم `node scripts/prepare-qa.cjs` و`node scripts/blog-qa.cjs` لاختبار المتصفح والصور والبحث والروابط ومعاينة الهاتف وصلاحيات النشر وعزل المسودة وتوقيعات المعاينة وإلغاء النشر. الاختبار ينظف مقاله المؤقت. احذف حسابات QA باستخدام `node scripts/cleanup-qa.cjs` بعد الانتهاء.


## تنسيق الاسم والوصف

الاسم والوصف المختصر لهما محرر Tiptap داخل نفس خاناتهما. يمكن تغيير حجم النص والبولد والمائل والتسطير والشطب والتمييز ولون GriidAi والمحاذاة والأسطر. الاسم يظل العنوان الرئيسي للصفحة؛ القوائم والجداول والروابط متاحة في الوصف والمقال، وليست داخل الاسم. التنسيق يظهر في الكارت والصفحة الداخلية والمعاينة.

الموقع يحتفظ بنسخة نصية نظيفة للاسم والوصف للرابط والبحث والقوائم والمشاركة. لا تتغير الروابط المنشورة عند تغيير التنسيق. حدود النص الحالية تظل مطبقة، والمحتوى القديم يعمل بنفس نصه دون الحاجة لإعادة إدخاله. Save يحفظ المسودة، وPublish يُظهر التنسيق للزوار.


## Tags

أضف موضوعات من خانة Tags باستخدام Enter أو Add tag، واحذفها بزر ×. تظهر في الكارت والصفحة وتفتح قائمة مفلترة عند الضغط عليها. التفاصيل في [دليل Tags](TAGS-AR.md).
