# تشغيل ونقل ربط Strapi

## حدود هذا العمل

هذه نسخة محلية منفصلة في `strapi-local-lab`، وليست تعديلًا منشورًا على dev. نسخة الموقع مأخوذة من الملفات الملتزمة في فرع التيم؛ لم نضم تغييرات التسعير المحلية المعلقة. التسعير يظل مستقلًا ويقرأ `PRICING_EMBED_URL` فقط.

الموقع يحتاج **سيرفر Node** للقراءة وقت الطلب. لا تكفي استضافة ملفات ثابتة أو GitHub Pages لهذا الربط. لا نحتاج إعادة بناء عند نشر Use Case، لكن تغييرات الكود نفسها تحتاج نشرًا طبيعيًا.

## محرر أجزاء المقدمة

الحقل `contentOrder` يحفظ ترتيب السيكشنز والأجزاء كله بمعرّفات محددة مثل `section:video` و`section:results` و`part:<id>`. قواعد التحقق والترتيب في `shared/page-order.cjs` تمنع تكرار السيكشنز أو إدراج معرّفات غير معروفة وتضم الأجزاء الجديدة تلقائيًا. السيكشنز الأساسية لا تُحذف؛ يمكن تحريكها، بما فيها العنوان والغلاف وأزرار النهاية. شريط التنقل والفوتر العام خارج هذا الترتيب. تحافظ القيم القديمة `placement` على ترتيبها السابق فقط عندما لا يوجد `contentOrder`. عند إخفاء الفيديو يظل موضعه محفوظًا للعودة إليه لاحقًا. صلاحيات الماركتنج تشمل قراءة وكتابة حقل الترتيب، ويظهر المحرر ضمن Page order بدل حقل JSON منفصل.

الحقل `parts` هو JSON منظم بمحرر Tiptap مخصص في `cms/src/admin/components/ContentParts.jsx`. يدعم عناوين H2–H4 والقوائم والمحاذاة والروابط وأحجام 12–64 واللون الثابت `#287b8d`، مع اختيار صورة من مكتبة Strapi لكل جزء ومكانها وعرضها ووصفها. قواعد التنظيف والعرض المشتركة في `shared/content-parts.cjs`، والتحقق من ملفات الصور على السيرفر في `cms/src/content-parts.js`. يتجاهل السيرفر رابط الصورة الذي يرسله المحرر ويقرأ الملف الحقيقي من Media Library بواسطة معرّفه. الصور ليست ملفات فيديو أو روابط صور حرة.

تُخفى حقول `question` و`overview` القديمة من المحرر لكنها تبقى بالقاعدة للحفاظ على الأصل. أول تشغيل يحوّل السجلات التي لا تحتوي `parts` فقط إلى جزء أول بنفس العنوان والنص، للمسودات والمنشور مع الحفاظ على تاريخ التعديل. إعادة التشغيل لا تستبدل أجزاء الماركتنج. محتوى الأجزاء يدخل في بحث All Use Cases. تغيير هذه الحقول لا يتطلب إعادة بناء الموقع عند النشر. انقل قاعدة البيانات ومكتبة الصور معًا؛ معرّفات الصور في `parts` يجب أن تظل مرتبطة بمكتبة Strapi المنقولة.

## التشغيل المحلي

استخدم Node LTS حديثًا متوافقًا مع Strapi 5، وnpm. التثبيت مثبت بـ`cms/package-lock.json`؛ استخدم `npm ci --prefix cms`.

من جذر التجربة:

```powershell
npm ci --prefix cms
npm run setup
npm run import
```

الإعداد يولّد الأسرار محليًا، ولا يطبعها. يكتب `cms/.env` و`website/.env`. لا ترفع أيًّا منهما. الأمر يفحص منافذ الموقع من 3000 حتى 3009 ولا يوقف أي عملية. إذا كان 1337 مشغولًا، غيّر منفذ CMS يدويًا كما هو موضح لاحقًا؛ لا توقف خدمة لا تخص هذه التجربة.

شغّل في نافذتين:

```powershell
npm run cms
```

```powershell
npm run site
```

افتح لوحة الإدارة وأنشئ حساب المالك. لا توجد بيانات دخول افتراضية. بعد إنشاء المالك، يضيف Super Admin أعضاء التيم من Settings → Administration Panel → Users ويدعوهم بأدوار Marketing Editor أو Marketing Publisher. لا يوجد تسجيل عام للزوار: امتداد `cms/src/extensions/users-permissions/strapi-server.js` يلغي مسارات حسابات الزوار والتسجيل والدخول واستعادة كلمة مرور الزوار، ويخفي User من Content Manager. دخول الأدمن ودعوات التيم واستعادة كلمة مرورهم تظل عبر نظام Administration Panel المنفصل. البيانات القديمة في `up_users` محفوظة لكنها لا تسمح بالدخول. الموقع العام يبقى متاحًا للزوار لقراءة المحتوى المنشور فقط.

الإعدادات الإدارية متاحة فقط للدور ذي الكود `strapi-super-admin`، مع حماية مساراتها الإدارية على السيرفر وإخفائها من القوائم. تعديل الملف الشخصي ومكتبة الصور يظلان متاحين حسب صلاحيات الحساب. حذف عناصر Use Case المتكررة وإعادة ترتيب العناصر الموجودة متاحان لـSuper Admin فقط؛ يسمح لباقي المحررين بإضافة العناصر وتعديل نصوصها. الحماية في `cms/src/admin-access.js` و`cms/src/use-case-rules.js`، وتخصيص الواجهة في `cms/src/admin/components/AdminRoleLayout.jsx` و`cms/src/admin/admin-navigation.css`؛ لا تعديلات داخل `node_modules`.

## إعدادات البحث والمشاركة والبيانات المنظمة

حقول `seo` و`editorial` JSON منظمة بمحررين مخصصين، و`sharingImage` علاقة Media أصلية مخفية من التخطيط العادي ويختارها محرر SEO. صلاحيات الماركتنج تُضاف لهذه الحقول في bootstrap دون منح صلاحيات إدارية. منطق التنظيف والقيم الافتراضية والتاجات والـJSON-LD في `shared/seo.cjs`، والواجهة في `SeoSettings.jsx` و`EditorialDetails.jsx`. المسار العام يقرأ النسخة المنشورة فقط، والمعاينة تقرأ المسودة بتوقيع وتفرض noindex/nofollow.

القيم الافتراضية تُحسب عند العرض ولا تُكتب فوق overrides الماركتنج. العنوان الافتراضي من عنوان الحالة، والوصف من Short description ثم نص الأجزاء، وصورة المشاركة من الغلاف. الـcanonical والروابط المنظمة وخريطة الموقع وrobots.txt تُبنى من `SITE_URL`؛ اضبطه على الدومين النهائي في إعدادات النشر. حقول canonical المخصصة لها الأولوية وتحتاج مراجعة إذا كانت تخص بيئة معاينة. الصفحات الثابتة كذلك تعيد توليد canonical وog:url وروابط صور المشاركة المحلية من نفس الإعداد، دون الاعتماد على دومين المعاينة القديم.

كل صفحة حالة تولّد WebPage وBreadcrumbList وOrganization. صفحة All Use Cases تولّد CollectionPage وItemList. يُضاف VideoObject فقط عند وجود فيديو وتاريخ رفع فعلي؛ العنوان والوصف والغلاف والرابط من المحتوى الحالي. لا نختلق مؤلفًا أو تاريخ رفع أو نتائج. بيانات الكاتب والمراجع والمصادر تظهر في الصفحة ويُعكس محتواها في JSON-LD. لا نعطي الماركتنج حق إدخال HTML أو script في حقول التاجات.

خريطة الموقع تعرض الحالات المنشورة، وكل صفحة تستخدم canonical لرابطها نفسه مع index/follow دائمًا. أُزيلت خيارات canonical والفهرسة واتباع الروابط وعنوان ووصف المشاركة المنفصلين، ولا تؤثر القيم القديمة في العرض. المشاركة تتبع اسم الصفحة وملخصها؛ صورة المشاركة قابلة للاختيار، ووصفها يأتي من Media Library. المسودات والمعاينات لا تدخل الخريطة وتظل noindex/nofollow.

مراجع: [توصيات Google لميزات AI](https://developers.google.com/search/docs/appearance/ai-features)، [بيانات الفيديو](https://developers.google.com/search/docs/appearance/structured-data/video)، [canonical](https://developers.google.com/search/docs/crawling-indexing/consolidate-duplicate-urls).

## المتغيرات: ما الذي نغيره وأين؟

| الملف | المتغير | وظيفته |
|---|---|---|
| `website/.env` | `STRAPI_URL` | عنوان Strapi الذي يستطيع سيرفر الموقع الاتصال به، بدون `/api` في آخره |
| `website/.env` | `STRAPI_PUBLIC_URL` | عنوان Strapi العام الذي يصل إليه المتصفح لتحميل الصور، وأصل لوحة الإدارة المسموح له بتضمين المعاينة |
| `website/.env` | `STRAPI_API_TOKEN` | مفتاح خاص على السيرفر للقراءة فقط |
| الملفان | `PREVIEW_SECRET` | نفس السر العشوائي في الخدمتين لتوقيع روابط المعاينة |
| الملفان | `SITE_URL` | العنوان الكامل للموقع، مثل `http://localhost:3000` أو دومين HTTPS النهائي |
| `website/.env` | `PORT`, `HOST` | منفذ وعنوان استماع سيرفر الموقع |
| `cms/.env` | `PORT`, `HOST` | منفذ وعنوان استماع Strapi |
| `cms/.env` | `STRAPI_PUBLIC_URL` | عنوان CMS العام المستخدم في تشغيل Strapi ولوحته |
| `website/.env` | `PRICING_EMBED_URL` | رابط التسعير الحقيقي، مستقل عن Strapi ولا يوجد اختيار localhost تلقائي |

مثال: إذا نقلت Strapi محليًا إلى 1338، غيّر `cms/.env` إلى `PORT=1338` و`STRAPI_PUBLIC_URL=http://localhost:1338`، وحدّث `STRAPI_URL` و`STRAPI_PUBLIC_URL` في `website/.env` إلى نفس المنفذ. أعد تشغيل الخدمتين.

إذا تغيّر منفذ الموقع إلى 3001، غيّر `website/.env` إلى `PORT=3001` و`SITE_URL=http://localhost:3001`، واجعل `SITE_URL` في `cms/.env` مطابقًا. هذا ضروري لرابط المعاينة وCSP. لا تعدّل HTML أو JavaScript الخاص بالمتصفح لتغيير عنوان CMS.

في الإنتاج يقرأ السيرفر متغيرات البيئة من منصة التشغيل؛ لها أولوية على `.env`. ضع الأسرار في مدير أسرار أو إعداد الخدمة، وليس في ملفات الواجهة أو build arguments عامة.

## المفتاح والصلاحيات

الاستيراد المحلي ينشئ Content API Token من نوع custom بصلاحيتي:

```text
api::use-case.use-case.find
api::use-case.use-case.findOne
```

ويضعه في `website/.env` فقط. لا يحصل المتصفح عليه، ولا يحتاج رفع الصور أو كتابة المحتوى. يمكن إنشاء مفتاح بديل من Settings → API Tokens بنفس الصلاحيات ونسخه إلى بيئة سيرفر الموقع. لا تفتح قراءة المسودات لدور Public، ولا تستخدم Full Access للواجهة.

خادم الموقع يفرض `status=published` في كل المسارات العامة. مفتاح القراءة يستطيع الوصول إلى المسودة حتى تعمل المعاينة، لكن هذا الطلب لا يحدث إلا بعد التحقق من توقيع الرابط وصلاحيته. `?preview=true` على رابط عام لا يغيّر المصدر.

## مصدر البيانات والقالب

- النموذج: `cms/src/api/use-case/content-types/use-case/schema.json`.
- قواعد الحفظ والنشر وقفل الرابط: `cms/src/use-case-rules.js`.
- تجهيز الغلاف: `cms/src/use-case-media.js`.
- المحرر المحدود والقص: `cms/src/admin/components/`.
- إعداد Preview وتوقيع الرابط: `cms/config/admin.js`.
- قراءة API وتتبّع جميع الصفحات: `website/scripts/cms-client.cjs`.
- العرض والقائمة وSolutions وخريطة الموقع: `website/scripts/cms-pages.cjs`.
- سيرفر الموقع الفعلي: `website/cms-server.cjs`، وهو أمر `npm start`.
- التنسيق الآمن والتحقق المشترك: `shared/content.cjs`.

احتفظ بترتيب `cms/`, `website/`, `shared/` عند النقل؛ هناك اعتماد مشترك على المجلد الأخير. `server.cjs` القديم موجود فقط للتشغيل الثابت الاختياري، وليس نقطة تشغيل الربط الجديد.

لا يوجد كاش لمحتوى أو صفحات Use Cases في المرحلة الأولى. الردود ترسل `Cache-Control: private, no-store`، والطلب الخلفي يقرأ من Strapi كل مرة. لا يوجد polling أو تحديث تلقائي لصفحة مفتوحة. الصور المقصوصة لها ملفات مستقلة، ويمكن تخزين ملفات الصور الثابتة لاحقًا بصورة منفصلة.

عند تعطل Strapi، تعطي صفحات الحالات 503 ورسالة عامة، ولا تعود للملفات القديمة. باقي الصفحات تستمر؛ قائمة الحالات تفرغ مؤقتًا ويظهر تنبيه في Solutions. الصفحات غير المنشورة تعطي 404، حتى عند طلب `/index.html` صراحة.

## المعاينة

توجد معاينة جانبية مخصصة ضمن إضافة لوحة الإدارة في `cms/src/admin/components/LivePreview.jsx`. تستخدم واجهات Strapi Community العادية لإضافة لوحة، ولا تُفعّل أو تتجاوز مزايا Live Preview المدفوعة. تنقل الحقول المعروفة فقط من النموذج إلى iframe الموقع، مع تحقق `event.origin` و`event.source` في الجانبين.

رابط المعاينة الموقّع مع `live=1` يعرض إطارًا فارغًا. عندما تصل الكتابة الحالية، يرسل الإطار طلب POST من نفس أصل الموقع إلى نفس الرابط؛ يتحقق السيرفر من التوقيع وصلاحيته وأصل الطلب وحجمه، ثم يعرض المحتوى بقالب الصفحة نفسه مع تنظيف النصوص والروابط. هذا الطلب لا يكتب في Strapi ولا يقرأ مسودات أخرى. الخانات الفارغة مسموحة للمعاينة فقط؛ قواعد النشر تبقى كما هي.

الملفات: `website/scripts/live-preview.cjs`, `website/dist/cms-live-preview.js`، ومسار المعاينة في `website/cms-server.cjs`. يتجدد الرابط كل 12 دقيقة، وتبقى المعاينة بلا كاش وبلا فهرسة. تغييرات الميديا قبل Save تُعرض بالقص المرئي؛ الملفات النهائية تُنتج عند Save.

Save ثم Open preview يستخدم المعاينة العادية المجانية. توقيع HMAC مرتبط بمعرف المستند والوقت، وصلاحيته 15 دقيقة. الصفحة ترسل `noindex,nofollow`, `no-store`, `Referrer-Policy: no-referrer`، وتسمح بالتضمين من أصل لوحة الإدارة المحدد في `STRAPI_PUBLIC_URL` فقط.

خلف reverse proxy، اضبط HTTPS والأصول الفعلية في البيئتين. إذا حجبت اللوحة المعاينة، راجع `SITE_URL` في إعداد `admin.preview.config.allowedOrigins` و`STRAPI_PUBLIC_URL` في الموقع؛ لا تستخدم `*` كحل.

## الاستيراد ونقل المحتوى

`npm run import` يقرأ الحالات السبع من ملف المصدر الأصلي وينقل الصور من أصول الموقع إلى Media Library، وينشئ غلافًا 16:9 وينشر الحالات الجديدة. يستخدم مفتاحًا خاصًا `legacy:<slug>`؛ تشغيله مرة أخرى يتجاوز السجلات الموجودة ولا يستبدل تعديلات الماركتنج ولا يعيد نشر حالة أُخفيت.

شغّل الاستيراد والخدمة متوقفة، وقبل أن يبدأ التيم تعديل المحتوى. إذا فشلت عملية استيراد جزئية، راجع السجل والمسودة المتأثرة قبل إزالتها وإعادة استيرادها؛ الأداة تتعمد عدم الكتابة فوق سجل موجود.

Git لا ينقل SQLite أو الصور المرفوعة. لنقل المحتوى بعد التجربة، استخدم أدوات export/import أو transfer الرسمية المتوافقة مع نفس إصدار Strapi، وتحقق من تضمين الملفات والعلاقات. خزّن النسخ المصدرة خارج Git لأنها قد تحتوي بيانات خاصة. خذ نسخة احتياطية قبل النقل، وراجع العدد والروابط والصور والصلاحيات بعده. مفاتيح API وإعدادات البيئة تُنشأ في البيئة المستهدفة بشكل مستقل.

## تجهيز الإنتاج بعد اعتماد التجربة

التيم ينشر Strapi كخدمة مستقلة، مع PostgreSQL وتخزين ملفات دائم عبر مزود رفع مناسب. يضاف برنامج تشغيل PostgreSQL إلى اعتماديات CMS عند اعتماد هذه البنية، وتضبط `DATABASE_CLIENT=postgres` وبيانات الاتصال وTLS من البيئة. لا تشغّل SQLite داخل حاوية مؤقتة ولا تعتمد على مجلد uploads داخلها.

ينشر الموقع كخدمة Node منفصلة تعمل بـ`npm start --prefix website`، مع المتغيرات الصحيحة. ملفات Docker النموذجية في جذر التجربة تستخدم سياق البناء من الجذر للمحافظة على `shared/`. ليست عملية نشر منفذة أو إعدادًا جاهزًا لكل مزود تخزين.

اضبط عدم تخزين مسارات `/use-cases/*`, `/preview/*`, صفحات Solutions ذات المحتوى المتغير، والقوائم المشتركة وخريطة الموقع في CDN أو reverse proxy خلال هذه المرحلة. أبقِ القراءة العامة مغلقة في CMS، وخصص المفتاح للقراءة فقط. اضبط النسخ الاحتياطي، الصور الدائمة، HTTPS، ربط الدومين وسياسات المعاينة، ثم اختبر Save/Publish/Unpublish قبل إتاحة الموقع.

## ملاحظات توافق محلية

المشروع مثبت على Strapi 5.59.0. ملف `cms/scripts/cli.cjs` يمنع CLI من قراءة `tsconfig.json` تابع لمشروع أب غير متعلق بهذا المشروع JavaScript. لا يعدّل ملفات المجلد الأب أو حزم node_modules.

ثُبت Sharp 0.34.5 عبر npm overrides لأن النسخة 0.35.5 المرفقة سببت خطأ تحميل مكتبة الصور على هذا الجهاز Windows. التحويل والرفع والقص اختُبرت محليًا. حافظ على lockfile وأعد اختبارات الصور عند ترقية الاعتماديات أو الانتقال لبيئة أخرى.

المراجع: [Preview](https://docs.strapi.io/cms/features/preview)، [Custom fields](https://docs.strapi.io/cms/features/custom-fields)، [Document Service middleware](https://docs.strapi.io/cms/api/document-service/middlewares)، [Tiptap configuration](https://tiptap.dev/docs/editor/getting-started/configure).

## حقول تنسيق الاسم والوصف

أُضيف `titleFormatting` و`summaryFormatting` كحقول JSON بمحرر `global::intro-richtext`، مع بقاء `title` و`summary` النصيتين للتوافق مع الاستيراد والروابط وSEO. الحقول النصية مخفية في تخطيط التحرير فقط، ويقوم المحرر والسيرفر بمزامنتها. تغيير النص مباشرة عبر API يمسح التنسيق القديم إن لم يعد مطابقًا. `shared/intro-formatting.cjs` ينظف المستندات ويرندرها دون HTML خام، ويمنع روابط أو بلوكات داخل عنوان H1. صلاحيات الحقلين مضافة لأدوار الماركتنج القائمة. المخطط يضيف عمودين JSON دون تحويل أو إعادة كتابة النصوص الحالية؛ احتفظ بنسخة قاعدة البيانات قبل ترقية نسخة منشورة.

التحقق: `npm test` ثم `node scripts/prepare-qa.cjs` و`node scripts/intro-editors-qa.cjs` و`node scripts/cleanup-qa.cjs`.


## إلغاء قسم المساهمين في Use Cases

محرر editorial في Use Cases يقتصر على تاريخ رفع الفيديو ومدته، ويختفي مع نوع image. normalizeUseCaseEditorial يتجاهل المؤلف والمراجع وقائمة المصادر القديمة عند العرض والتحقق، ويحتفظ بمعلومات الفيديو الصحيحة. أُزيل section:credits من ترتيب الصفحة. ميتاداتا كاتب البلوج وصورته وLinkedIn لا تتغير؛ لا يوجد حذف جماعي للسجلات القديمة.
